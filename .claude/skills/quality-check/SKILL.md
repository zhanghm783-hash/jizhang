## 质检步骤

1. **摸清近期改动**：运行 `git status --short` 和 `git diff --stat`，了解最近改了什么，检查时重点盯这些文件。
2. **类型检查**（查低级错误：字段名拼错、类型对不上等）：
   运行 `npx vue-tsc --noEmit`，等它跑完。
3. **构建检查**（查能否正常编译出成品）：
   运行 `npm run build`，等它跑完。
4. **汇总报告**，用大白话向用户汇报：
   - 检查了哪几项、各是什么结果
   - 发现的问题按"必须修 / 建议修 / 可忽略"分三档
   - 每个问题说明：在哪个文件哪一行、什么问题、为什么算问题
5. **不擅自改代码**：报告后等用户确认，同意后再修复，修复时逐个说明改了什么。

## 注意事项

- 类型检查和构建检查各要几十秒，属正常现象。
- 检查命令本身报环境错误时（比如工具缺失），如实汇报，不要瞎猜原因。
- 检查全部通过也要如实报告"全部通过"，不要为了显得有成果而夸大问题。
- 全部通过但发现明显的代码异味（比如复制粘贴的重复代码、写死的魔法数字），可以作为"建议修"一并汇报。
